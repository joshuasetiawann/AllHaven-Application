# AllHaven v4.3.0 - Release Notes

Date: 2026-08-13

AllHaven 4.3.0 is a security and integrity release. A full application audit produced ten findings; all ten are closed and retested, and an adversarial closure review that followed fixed a further set of authentication, synchronization, resource-exhaustion, and truthfulness defects. The repository structure was tidied in the same pass. No feature was removed and no API contract changed.

## Security

- **Secret encryption replaced.** API keys and integration credentials now use versioned AES-256-GCM envelopes with context-bound AAD, reads against previous keys, and a repeatable rotation CLI (`backend/app/cli/rotate_secrets.py`). The previous custom construction is gone.
- **Upload limits enforced before allocation.** An ASGI pre-parser body ceiling rejects oversized requests up front, chunked uploads return a canonical 413, Drive writes stream to disk, and Knowledge carries its own limit.
- **Document parsers bounded.** DOCX extraction uses bounded ZIP/XML with defused XML and a parser concurrency cap. PDF parsing gained per-stream and cumulative decoded-output limits, per-array and cumulative structural-item limits, bounded page-tree traversal, and cycle/fan-out/depth caps, with a metadata-only fallback. A 3 MB nested-array reproduction went from ~9.45 s / 52.6 MiB to 0.22 s / 1.64 MiB.
- **Mobile credentials moved to the platform vault.** Tokens and Supabase sessions use `@aparajita/capacitor-secure-storage` (iOS Keychain, Android AES-GCM keyed by Android Keystore). Upgrades migrate legacy `Preferences` values write-first and delete the plaintext entries; there is no insecure fallback.
- **CSP no longer allows `unsafe-inline` for scripts.** Web serves a per-request nonce CSP; the mobile static build is hardened with route-specific script hashes.
- **Bearer logout is enforceable.** Logout persists a SHA-256 revocation identifier and immediately rejects the same local or Supabase token. Logout bypasses failed-login rate buckets, trusted-proxy client partitioning is explicit, and stale token-verifier caching was removed.
- **Registration hardened.** A profile or remote Auth account is never adopted by email alone. Concurrent registrations map deterministically to 409, email length is bounded, and a missing account still performs dummy PBKDF2 work. Revision `0029` enforces case-insensitive email uniqueness behind a collision-safe preflight.
- **Session refresh is atomic.** A compare-and-swap guarantees one old cookie/CSRF pair yields exactly one new session.
- **Mobile bearer transport fails closed** for loopback, malformed or ambiguous IPs, and public cleartext HTTP. Cleartext is limited to canonical RFC1918 or Tailscale bridges; public backends require HTTPS.
- **Frontend dependency graph patched.** Complete and production-only `npm audit` both return zero vulnerabilities.

## Fixed

- **System Control told the truth about containers.** Container-aware probes replaced the host-only check that reported healthy containers as stopped; unavailable and unknown states are now distinct, and controls that cannot act are stripped rather than shown as working.
- **Supabase Connect, System Control, and logout no longer report success** when the backend operation failed or was disabled.
- **`127.0.0.1` works as a production-local origin.** Same-port loopback CORS and URL resolution are exact; alternate and hostile origins stay denied.
- **Task deletion asks first.** An accessible confirmation dialog replaced immediate deletion.
- **Relational integrity restored.** Composite tenant foreign keys plus reconciliation migrations (`0022`, `0025`) close cross-workspace references, with collision-safe upgrades.
- **Supabase sync is tenant-safe.** Fetch and apply are tenant-filtered, cross-workspace primary-key collisions are rejected, pagination uses stable `(timestamp, id)` cursors, pull no longer skips unsent local rows, and remote membership/profile ordering is foreign-key safe. Configuration and credential ciphertext is excluded from mobile sync.
- **RLS reconciled.** Migrations `0023`, `0026`, and `0027` remove arbitrary legacy policies, keep secret tables inaccessible to clients, refuse email-only profile claims, and normalize the owner of every `SECURITY DEFINER` helper.

## Changed

- **Repository structure tidied.** Eight audit reports and one results file moved out of the repository root into `docs/reports/`. `docs/v4/` was dissolved: its release notes joined `docs/releases/` under the existing `vX.Y.Z.md` convention, its point-in-time reports joined `docs/reports/`, and its living guides moved to `docs/` as `TAILSCALE_SETUP.md`, `SUPABASE_MIGRATION.md`, and `DOWNLOADS.md`. `docs/deploy/` became `docs/sql/`, which no longer collides with the root `deploy/` and describes its contents. Every internal link was updated; the repository has no broken relative markdown links.

## Deployment

- Run `alembic upgrade head` before starting 4.3.0. On PostgreSQL the email-uniqueness preflight aborts safely at `0028` if colliding rows exist — resolve the duplicates, then re-run. No partial indexes are left behind.
- For a hosted Supabase project, run the same upgrade with `ALLHAVEN_DB_TARGET=supabase DATABASE_URL=<supabase>`. See `docs/SUPABASE_MIGRATION.md`.
- Rotate integration secrets after upgrading so they are re-wrapped in the new envelope format: `python -m app.cli.rotate_secrets`. Old-key reads keep working until you do.
- Mobile clients migrate their stored credentials on first launch; no user action is required.
